Tests manuels One Piece pour l'API Manga News
============================================

But
---
Ce fichier sert de check-list simple et concrète pour vérifier qu'une instance est réellement exploitable.

Il couvre :
- santé
- auth publique et admin
- recherche
- résolution
- lookup volume
- fiches série / volume
- news
- planning
- endpoints admin
- ETag / 304
- smoke test batch

Base URL recommandée
--------------------
http://localhost:8017/v1

Variables utiles
----------------
Linux / macOS
export BASE_URL="http://localhost:8017/v1"
export TOKEN="ton_token_public"
export ADMIN_TOKEN="ton_token_admin"

Windows PowerShell
$env:BASE_URL = "http://localhost:8017/v1"
$env:TOKEN = "ton_token_public"
$env:ADMIN_TOKEN = "ton_token_admin"

Règle simple
------------
- endpoints publics : header Bearer avec TOKEN
- endpoints admin : header Bearer avec ADMIN_TOKEN
- si pas d'auth chez toi, enlève simplement les headers Authorization

Pré-check conseillé
-------------------
1) l'API est démarrée
2) /v1/health répond
3) si auth activée, les bons tokens sont définis
4) si legacy routes sont off, ne teste pas /health sans /v1

Santé
-----
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/health"

Trouver le tome 91 de One Piece
-------------------------------
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/search?q=one%20piece%20tome%2091&kind=volume&mode=all&limit=10"

Attendu : au moins un candidat volume exploitable, avec series_slug et volume_slug.

Résoudre directement le meilleur match du tome 91
-------------------------------------------------
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/search/resolve?q=one%20piece%20tome%2091&kind=volume&limit=10"

Attendu : data.best.kind = volume et volume_slug exploitable.

Lookup volume direct par série + numéro
---------------------------------------
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/lookup/volume?series=One%20Piece&number=91&limit=10"

Attendu : data.volume complet, avec number=91 et number_int=91 si détecté.

Fiche volume 91
---------------
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/volume/One-Piece/vol-91"

Vérifications conseillées :
- title présent
- number = 91
- number_int = 91
- publication_date présent si disponible
- isbn_ean présent si disponible
- source_url présent

Fiche volume 91 via URL
-----------------------
curl -sS -G -H "Authorization: Bearer $TOKEN" "$BASE_URL/volume/by-url" --data-urlencode "url=https://www.manga-news.com/index.php/manga/One-Piece/vol-91"

curl -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/news/volume/One-Piece/vol-91?limit=10"

Planning VF filtré One Piece

Admin cache stats
-----------------
curl -sS -H "Authorization: Bearer $ADMIN_TOKEN" "$BASE_URL/admin/cache/stats"

Admin metrics
-------------
curl -sS -H "Authorization: Bearer $ADMIN_TOKEN" "$BASE_URL/admin/metrics"

Admin invalidate série
----------------------
curl -sS -X POST "$BASE_URL/admin/cache/invalidate" -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" -d '{"resource_url":"https://www.manga-news.com/index.php/serie/One-piece-Edition-originale"}'

Admin invalidate volume
-----------------------
curl -sS -X POST "$BASE_URL/admin/cache/invalidate" -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" -d '{"resource_url":"https://www.manga-news.com/index.php/manga/One-Piece/vol-91"}'

ETag / 304
----------
1) récupère d'abord un ETag :
curl -i -sS -H "Authorization: Bearer $TOKEN" "$BASE_URL/series/One-piece-Edition-originale"

2) rejoue avec If-None-Match :
curl -i -sS -H "Authorization: Bearer $TOKEN" -H 'If-None-Match: "<etag-precedent>"' "$BASE_URL/series/One-piece-Edition-originale"

Attendu : 304 si rien n'a changé.
